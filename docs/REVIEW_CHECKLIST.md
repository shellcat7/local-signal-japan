# Review Checklist

## このUIでユーザーが誤解しそうな点

- 補助スコアを地域ランキングのように読んでしまう可能性があります。
- 架空データであることは表示していますが、実在自治体コードを使うため、デモ値を実統計と誤解する可能性があります。
- 近隣自治体比較はデモ固定値のため、実データでは比較対象の選定ロジックが必要です。

## 情報が多すぎる画面

- `/demo` は初期画面にレポート全文まで出るため、スマートフォンでは情報量が多くなります。
- 将来的にはレポート欄をタブまたは折りたたみ表示にする余地があります。

## 出典表示が弱い画面

- 指標カードには出典を表示しています。
- チャートの時系列サンプルは固定デモ配列のため、実データ化時には各系列の出典を追加してください。

## 欠損データ表示が弱い画面

- 欠損はスコアピルで表示されます。
- 欠損理由の分類、代替データ候補、取得失敗か未提供かの区別は未実装です。

## セキュリティ上の不安がある箇所

- MVPはモックのみですが、実connector追加時にAPIキーをWorker側へ閉じ込める実装レビューが必要です。
- WorkerのCORS許可はローカル開発向けです。本番ドメインに合わせて制限してください。
- CIは初期テンプレートのため、ロックファイル導入後に frozen lockfile を有効化してください。

## 公開前に直すべき優先順位

1. 実データ利用時のsource metadataをカードとレポートに追加する。
2. Workerの本番CORS設定を公開ドメインへ絞る。
3. CLI fixtureを複数自治体対応にする。
4. `/demo` のモバイル表示でレポート欄を整理する。
5. Cloudflare Previewで視覚確認を行う。

## OSSとして他人が使いにくい箇所

- connectorの実装はまだmockのみです。
- scoring formulaはコード上では単純平均で、外部設定できません。
- npm公開用のpackage export設計はMVP最小限です。

## Cloudflare公開時に注意すべき箇所

- SecretsはCloudflare側で設定し、設定ファイルへ直書きしない。
- D1はMVPでは使わず、検索履歴保存も行わない。
- PagesのPreview Deploymentで `/demo` を確認してから本番公開する。
