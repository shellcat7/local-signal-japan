# まちのものさし（Local Signal Japan）

全国の市区町村について、公的統計（統計ダッシュボード、総務省「ふるさと納税に関する現況調査結果」）から作った検証済みのデータセットを読む。同梱の `scripts/lsj.mjs` で、7指標の値・基準時点・補助スコア・全国順位と、くらしの指標22項目の値・基準時点・全国順位を取得する。

## いつ使うか

- 日本の市区町村の人口・人口増減、高齢化率、転入・転出、事業所数、完全失業率、所得、財政力を聞かれたとき。
- 平均寿命、2050年の推計人口、外国人住民の割合、婚姻率、出生率、高齢者の一人暮らし、通勤・通学の手段、空き家率、住宅の広さ、医師や図書館の数、ごみ、ふるさと納税を聞かれたとき。
- 「高齢化率が25%以下で、所得が400万円以上の市区町村は？」「空き家率が20%以下で人口1万人以上の市区町村を、ふるさと納税の受入額の順に」のように、数値の条件に合う市区町村を挙げるとき。
- ランキング（上位・下位）、都道府県内や人口規模別の順位、特集（2050年に人口が半分以下になる見込みの市区町村など）、複数の市区町村の比較を求められたとき。
- ある市区町村が全国で目立つ点（全国の上位・下位10位以内に入る項目）を聞かれたとき。

Web検索や記憶で答えない。条件に合う市区町村の全件と、数値の基準時点を保証できるのは、このデータセットだけ。
ここにない項目（地価、犯罪、気候、合計特殊出生率など）は対象外。対象外だと伝え、別の手段で調べる。

## コマンド

`scripts/lsj.mjs` は、この SKILL.md があるフォルダからの相対パス。追加のインストールは要らない。出力は JSON（人に見せる表が要るときだけ `--text` を付ける）。

```bash
node scripts/lsj.mjs indicators                      # 7指標とくらしの指標のキー・単位・基準時点・全国の分布・出典
node scripts/lsj.mjs search 府中                      # 名前・よみがな・5桁コードで市区町村を探す
node scripts/lsj.mjs show 13101                      # 1つの市区町村の全指標・くらしの指標・全国で目立つところ
node scripts/lsj.mjs show 東京都府中市
node scripts/lsj.mjs compare 13101 横浜市青葉区 14100  # 2〜5つの市区町村を並べる
node scripts/lsj.mjs screen --where "aging<=25" --where "income>=400" --pref 東京都 --sort income --limit 0
node scripts/lsj.mjs screen --where "vacancy<=20" --size over-10k --sort furusatoReceipts
node scripts/lsj.mjs topics                          # 特集ランキングの一覧
node scripts/lsj.mjs topics half-by-2050 --limit 0   # 特集ランキング（計算は screen と同じ）
```

### screen（条件に合う市区町村をもれなく抜き出す）

- `--where "<キー><演算子><数値>"`: 条件。演算子は `>=`（以上）と `<=`（以下）だけで、両端を含む。何度でも指定でき、すべてを満たす市区町村が残る。同じキーに両方を付けると範囲になる。数値に単位や桁区切りは付けない。金額（円）のキーは円の数値で書く（10億円以上なら `furusatoReceipts>=1000000000`）。
- `--sort <値>`: 並べ替えに使う値。`residents`（人口、既定）、`overall`（総合補助スコア）、指標キー、くらしの指標キーのどれか。
- `--order <順>`: `desc`（大きい順、既定）か `asc`（小さい順）。
- `--pref <都道府県>`: 都道府県名（`東京都`）か2桁コード（`13`）。
- `--size <人口規模>`: `all`（既定）、`over-10k`、`under-10k`、`10k-50k`、`50k-200k`、`over-200k`。
- `--limit <件数>`: 出力する件数。既定は20、`0` で全件。
- `--csv`: BOM付きUTF-8のCSVで出力する（くらしの指標はすべての列が入り、金額は円の数値）。

指標キー（7指標。補助スコアあり）:

| キー         | 指標値                            | 単位   |
| ------------ | --------------------------------- | ------ |
| `population` | 5年間の人口増減率                 | %      |
| `aging`      | 高齢化率（65歳以上人口の割合）    | %      |
| `migration`  | 転入超過率（直近3年平均）         | %      |
| `business`   | 人口千人当たりの民営事業所数      | 事業所 |
| `employment` | 完全失業率（国勢調査）            | %      |
| `income`     | 納税義務者1人当たりの課税対象所得 | 万円   |
| `fiscal`     | 財政力指数                        | なし   |

`population` は人口そのものではなく、5年間の増減率。人口の規模で絞るには `--size`、人口の順に並べるには `--sort residents` を使う。

くらしの指標キー（補助スコアなし。値と全国順位だけ）:

| キー                | 項目                                     | 単位           |
| ------------------- | ---------------------------------------- | -------------- |
| `lifeFemale`        | 平均寿命（女性）                         | 年             |
| `lifeMale`          | 平均寿命（男性）                         | 年             |
| `projection2050`    | 2050年の推計人口（2025年比の増減率）     | %              |
| `foreignShare`      | 外国人住民の割合                         | %              |
| `marriageRate`      | 婚姻率（人口千人当たり）                 | なし           |
| `birthRate`         | 出生率（人口千人当たり）                 | なし           |
| `elderlyAlone`      | 高齢者の一人暮らし世帯の割合             | %              |
| `commuteRail`       | 通勤・通学に鉄道・電車だけを使う人の割合 | %              |
| `commuteCar`        | 通勤・通学に自家用車だけを使う人の割合   | %              |
| `commuteBike`       | 通勤・通学に自転車だけを使う人の割合     | %              |
| `commuteWalk`       | 通勤・通学に徒歩だけを使う人の割合       | %              |
| `vacancy`           | 空き家率                                 | %              |
| `floorArea`         | 1住宅当たりの延べ面積                    | ㎡             |
| `doctors`           | 医師の数（人口10万人当たり）             | 人             |
| `libraries`         | 図書館の数（人口10万人当たり）           | 館             |
| `garbage`           | 1人1日当たりのごみの量                   | g              |
| `recycling`         | ごみのリサイクル率                       | %              |
| `furusatoReceipts`  | ふるさと納税の受入額                     | 円             |
| `furusatoPerCapita` | ふるさと納税の受入額（住民1人当たり）    | 円             |
| `furusatoCostShare` | ふるさと納税の受入額に占める費用の割合   | %              |
| `furusatoOutflow`   | ふるさと納税による住民税の控除額         | 円             |
| `furusatoNet`       | ふるさと納税の受入額と住民税の控除額の差 | 円（負もある） |

手順:

1. まず `--limit` を付けずに実行し、`matched`（該当数）を確かめる。
2. 全件を答えに載せるなら、`--limit 0` で取り直す。`truncated` が `true` の結果を「全件」として扱わない。
3. 該当が多いとき（目安は100件超）は、全件を会話に流し込まない。`--limit 0 --csv > 結果.csv` で保存して渡し、本文には該当数と、どの順で何件を示したかを書く。

### topics（特集ランキング）

`topics` で特集の一覧（`id`・`title`・`lead` と、並べ方・条件）、`topics <id>` でその一覧を返す。中身は screen と同じ形で、`topic` に見出しと説明が入る。`--pref` と `--limit`（既定20）だけ指定できる。条件を変えたいときは screen を使う。

### 市区町村の指定

5桁の市区町村コードか名前で指定する。同じ名前が複数あると（例: 府中市は東京都と広島県にある）、終了コード1で `error.code` が `ambiguous`、`error.candidates` に候補が返る。推測で選ばない。文脈で決まらなければユーザーに確かめ、コードか「都道府県名＋市区町村名」で実行し直す。

### データの場所

既定では `https://local-signal-japan.pages.dev/data/` を読む。`--data <フォルダまたはURL>` か環境変数 `LSJ_DATA` で変えられる（リポジトリの中なら `LSJ_DATA=apps/web/public/data`）。
読めないときは `error.code` が `data-unavailable`、`invalid-data`、`unsupported-schema` のどれかになる。そのときは数値を記憶や推測で補わず、取得できなかったと伝える。

## 出力の読み方

- `value` は値。単位は `unit`、基準時点は `period`（指標ごとに違う。`source.periods` にも入っている）。
- `score`（補助スコア）は7指標だけにある。全国の市区町村（政令指定都市の区を除く基準集団）の中での位置を表すパーセンタイルで、0〜100、50が全国の中央。値が大きいほど高い。ただし高齢化率（`aging`）と完全失業率（`employment`）だけは、値が小さいほど高い。向きは集計上の約束で、良し悪しの判定ではない。
- くらしの指標（`facts`）には補助スコアがない。`rank` / `rankTotal` は、政令指定都市の区を除く値のある市区町村の中で、値が大きい順に数えた順位とその母数。`basis` は値を求めたもとの数（例: 外国人住民の数と住民の数）。
- 金額（`unit` が `円`）は円の数値。`valueText`・`moneyTexts`・`medianText` は「18.9億円」のように書いた文字列で、答えにはこちらを使ってよい（桁を読み違えない）。
- `highlights`（全国で目立つところ）は、全国の上位・下位10位以内に入る項目を決まった規則で抜き出したもの。同じ値の市区町村も数に入れて端から10以内のときだけ選ぶ。`phrase` は「全国で最も高い」「人口1万人以上の市区町村で3番目に長い」のような決まった言い方で、`limited` が `true` なら人口1万人以上の市区町村の中での順位。
- `screen` と `compare` では、行の直下の `population` が住民基本台帳人口（人）、`values.population` が5年間の人口増減率（%）。取り違えない。くらしの指標の値は `facts` に入る。
- `overallScore`（総合補助スコア）は、7指標の補助スコアの単純平均。4指標以上そろうときだけ算出し、足りなければ `null`。くらしの指標は含まない。
- `rank` は、基準集団の中で値が大きい順に数えた順位（同じ値は同順位）。良し悪しの順ではない（高齢化率の1位は、高齢化率が最も高い市区町村）。
- `screen` と `topics <id>` の `rank` は、条件で絞り込んだ中での順位。全国順位ではない。`total` は対象の数（政令指定都市の区を除き、都道府県・人口規模で絞ったあと）、`matched` は条件に合った数、`rows` はそのうち出力した分。
- `null` は欠損。「欠損」と書く。0や低い値として扱わず、平均や大小の比較にも入れない。理由は `missing` にある（空き家率と住宅の広さは、市と人口1万5千人以上の町村だけが集計の対象）。
- `screen` で `rank` が `null` の行は、条件には合うが、並べ替えに使う値が欠損の市区町村。該当として数え、順位なしと書く。
- 条件を付けた指標が欠損の市区町村は、その条件に該当しない（例: 特別区は `fiscal` の条件に一切かからない）。答えに影響するときは、そのことを書く。

## 回答の必須ルール

1. 数値には必ず、指標名（`metricLabel` か `label`）・統計名（`statName`）・基準時点（`period`）を、数値ごとに添える。基準時点は指標ごとに違うので、まとめて1つにしない。例: 「高齢化率 16.2%（国勢調査、2025年）」「ふるさと納税の受入額 18.9億円（令和7年度（2025年度））」。
2. 条件で抜き出した結果は、該当した市区町村をすべて挙げる。挙げきれないときは、該当数（`matched`）と、どの順で何件までを示したかを書く。使った条件（指標・しきい値・都道府県・人口規模・並び順）も書く。
3. ふるさと納税の値を使うときは、受入額は返礼品・送料・広告などの費用を差し引く前の金額であること、住民税の控除額は地方交付税を受けている市区町村では多くが交付税で補われ、そのまま減収になるわけではないことを書く。受入額と控除額の差（`furusatoNet`）は実際の収支ではない目安だと書く。
4. 人口の少ない市区町村（目安は1万人未満）の値を述べるときは、少数の増減で大きく動くことを書く。とくに `smallAreaCaution` が `true` の指標（婚姻率・出生率・医師と図書館の数）と、住民1人当たりのふるさと納税受入額。
5. データにないことを補わない。将来の見通し、原因の説明、データにない年や指標の値を推測で書かない。2050年の推計人口は、過去の傾向が続いた場合の推計で、予測や目標ではないと書く。
6. 良し悪しを判定しない。順位や「全国で目立つところ」を、良い・悪い、住みやすい、衰退している、おすすめのような評価として書かない。値と全国の中での位置だけを述べる。評価を求められたら、判断材料として値を示し、判断はユーザーに委ねる。
7. 答えの最後に、`source.citation` の各行をそのまま入れる（統計ダッシュボードの出典とクレジット。ふるさと納税の値を使ったときは総務省の出典も入る）。例:

   > 出典: 統計ダッシュボード（https://dashboard.e-stat.go.jp/）のデータを加工して作成（データ取得日: YYYY-MM-DD）
   >
   > 出典: 総務省「ふるさと納税に関する現況調査結果」を加工して作成
   >
   > このサービスは、統計ダッシュボードのAPI機能を使用していますが、サービスの内容は国によって保証されたものではありません。

   ふるさと納税の値を答えに使っていないときは、総務省の行は省いてよい。

## 限界

- データは `source.fetchedAt`（データセットの `generatedAt`）の時点のもの。それより後に公表された値は入っていない。最新かどうかを聞かれたら、取得日と各指標の基準時点を答える。
- 基準時点は指標ごとに違う。国勢調査に基づく指標（高齢化率、完全失業率、通勤手段、高齢者の一人暮らし）は5年に一度、住宅・土地統計調査（空き家率、住宅の広さ）と市区町村別生命表（平均寿命）も5年ごとにしか更新されない。
- 政令指定都市の区には全国順位がなく（`rank` は `null`）、`screen`・`topics`・全国で目立つところの対象にもならない（市全体と重複するため）。所得・財政力指数・ふるさと納税は区の単位では収録されていない。区の値は `show` と `compare` で見る。
- 東京都の特別区は、財政力指数が欠損。
- 値は表示する桁に丸めてある（率は小数第1位など）。`screen` の条件は、この丸めた値と比べる。
- 過去の値は、`show` の `indicators[*].facts` と `change`（5年前の値、5年前比）にある範囲だけ。くらしの指標は最新の1時点だけ。
